# RD Online Shop — Cross-Platform Stability Audit

Target platforms for this pass:

- Windows Desktop
- Android
- iPhone / iPad (iOS)
- macOS

The supplied project archives were combined and the complete `lib/` tree (55 Dart files after cleanup) plus Android, iOS, Windows, macOS, assets, `pubspec.yaml`, `pubspec.lock`, Firebase configuration, and Firestore rules were reviewed for platform-specific breakpoints.

## Stability changes applied

1. **Flutter/Dart version guard**
   - `pubspec.yaml` now requires Dart `>=3.12.0 <4.0.0`.
   - Flutter is constrained to `>=3.44.4 <3.45.0` for this stabilized package.
   - This is intentional: it prevents accidentally running this source with a different Flutter engine (for example 3.47.x) and then reusing generated Windows wrapper/cache files from another SDK.

2. **Windows black-screen/startup protection**
   - `lib/main.dart` now renders Flutter first and initializes Firebase/auth/data inside `StartupGate`.
   - If startup fails, RD shows the actual startup error and a Retry button instead of leaving an unexplained black window.
   - FCM background registration is performed only on supported mobile platforms.

3. **Central platform capability layer**
   - Added `lib/services/platform_capabilities.dart`.
   - FCM, native geocoding, embedded WebView, and QR-camera support are decided in one place instead of scattered checks.

4. **Windows-safe geocoding**
   - Windows does not have a geocoding implementation in the current dependency set.
   - Checkout now avoids initializing/calling native geocoding on Windows.
   - GPS coordinates and manual address fallbacks remain usable.
   - Ride booking now also enables native geocoding on macOS, where the Darwin implementation is available.

5. **Windows-safe eSewa screen**
   - `webview_flutter` has Android/Apple implementations in this lockfile but no Windows implementation.
   - The eSewa page no longer creates a WebView on Windows.
   - Windows gets a safe explanatory screen and can return to checkout instead of crashing the app.

6. **Windows-safe delivery QR confirmation**
   - `mobile_scanner` is not registered for Windows in the supplied dependency metadata.
   - Windows now uses the existing secure 6-digit OTP confirmation path instead of trying to start a camera scanner.
   - Android/iOS/macOS keep QR camera scanning.

7. **Android permissions completed**
   - Internet
   - Fine/coarse location
   - Microphone
   - Camera
   - Android 13+ notification permission

8. **iPhone/iPad permission descriptions completed**
   - Camera
   - Microphone
   - Speech recognition
   - Photo library
   - Location while in use
   - Remote-notification background mode added for FCM background delivery support.

9. **macOS sandbox permissions completed**
   - Outbound network client (needed by Firebase/HTTP)
   - Camera
   - Audio input
   - Location
   - User-selected files
   - Matching Info.plist privacy usage descriptions were added.

10. **Generated/machine-specific files removed**
    - `windows/flutter/ephemeral/`
    - `ios/Flutter/ephemeral/`
    - `macos/Flutter/ephemeral/`
    - iOS generated Flutter paths/environment files
    - Android `local.properties`
    - Android Gradle/build caches and crash logs
    - `.flutter-plugins-dependencies`
    - temporary platform test file

    These files must be regenerated by the Flutter SDK on the computer that is actually building the app. Keeping them in a project ZIP is one of the main ways SDK/engine files get mixed across versions.

11. **Accidental installer files removed from app assets**
    - `.exe`
    - `.msi`
    - `.winmd`

    Product/category/image assets remain intact.

12. **Cross-platform `.gitignore` hardened**
    - Machine-specific Flutter/Android/iOS/macOS/Windows generated files are now explicitly ignored.

## Existing cross-platform work kept intact

- Home page already includes touch + mouse + trackpad drag devices and responsive product grid logic.
- Seller/product image upload flows use Cloudinary URLs for cross-device display.
- Firebase options already contain Android, iOS, macOS, Windows and web configurations.
- Shared Preferences, Firebase Auth, Firestore, URL Launcher, Share Plus, Path Provider and Speech-to-Text have implementations for the requested platforms in the supplied dependency metadata.

## Important build rule

Do not copy generated `ephemeral`, `build`, `.dart_tool`, `local.properties`, or generated Xcode environment files between machines or between Flutter SDK versions.

For this stabilized package, use **Flutter 3.44.4** on every development machine. On macOS, install the macOS build of Flutter 3.44.4; do not copy the Windows Flutter SDK folder to the Mac.

## Windows verification

From the project root, using the same Flutter 3.44.4 SDK that successfully rendered RD on this laptop:

```powershell
& "$env:USERPROFILE\Downloads\flutter_windows_3.44.4-stable\flutter\bin\flutter.bat" pub get
& "$env:USERPROFILE\Downloads\flutter_windows_3.44.4-stable\flutter\bin\flutter.bat" analyze --no-pub
& "$env:USERPROFILE\Downloads\flutter_windows_3.44.4-stable\flutter\bin\flutter.bat" run -d windows
```

Then test Android with the same source tree and same Flutter 3.44.4 SDK:

```powershell
& "$env:USERPROFILE\Downloads\flutter_windows_3.44.4-stable\flutter\bin\flutter.bat" run -d <ANDROID_DEVICE_ID>
```

## iOS/macOS verification

A Mac with Xcode is required for the real Apple compile/signing test:

```bash
flutter --version
flutter pub get
flutter analyze --no-pub
flutter run -d macos
flutter devices
flutter run -d <IOS_DEVICE_OR_SIMULATOR>
```

Use Flutter 3.44.4 on that Mac as well.

## Static validation performed on the prepared package

- All 55 Dart source files were included in the scan.
- Relative Dart imports were checked for missing files.
- `pubspec.yaml` was parsed and declared asset paths were checked.
- Android manifest XML was parsed.
- iOS/macOS plist and entitlement files were parsed.
- Machine-specific absolute Windows/macOS/Linux development paths were checked after cleanup.
- Generated `ephemeral` folders and accidental executable installers were checked after cleanup.
- Critical WebView, QR scanner, FCM and geocoding platform guards were checked.
- Result of these structural/static checks: **0 detected errors**.

A real iOS/macOS binary cannot be compiled without a macOS/Xcode environment, so Apple signing/build verification remains a machine-side final test rather than something that can be truthfully claimed from this audit alone.

## Firebase note

`firebase.json` references a `functions/` source folder, but no `functions/` folder was included in the supplied archives used for this package. This does not block Android/Windows/iOS/macOS client builds. It matters only when deploying Firebase Cloud Functions (for example future server-side FCM automation).

## Web note

The supplied `web/` folder is retained, but Web was not one of the four requested certified targets in this pass. Some existing legacy product-image code still uses `dart:io`, so this package should not be described as Web-ready yet.
